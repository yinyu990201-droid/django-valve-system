# 企业级插装阀资料管理平台 - 应用部署文档

## 1. 部署目标
将平台部署到云端 Linux 服务器（如阿里云、腾讯云、AWS、Azure 的 Ubuntu/CentOS 实例）。

## 2. 前置条件
- 已安装 Docker。
- 已安装 Docker Compose（或 Docker 自带 compose）。
- 服务器开放端口（示例：8000）。
- 具备 Git 拉取代码能力。
- 如需运行自动化测试，需具备 Python 虚拟环境和项目依赖。
- 生产部署使用 PostgreSQL，推荐直接使用项目提供的 `docker-compose.prod.yml`。

## 3. 部署步骤

### 3.1 拉取代码
```bash
git clone <your-repo-url>
cd valve
```

### 3.2 配置环境变量
```bash
cp .env.example .env
```
编辑 `.env`，重点修改：
- `SECRET_KEY`
- `ADMIN_PASSWORD`
- `POSTGRES_PASSWORD`
- `DATABASE_URL`
- `SHOW_DEMO_CREDENTIALS=false`

建议试用环境额外关注：
- `SESSION_COOKIE_SECURE`
- `DATABASE_URL`

### 3.3 启动 PostgreSQL 与应用
```bash
docker compose -f docker-compose.prod.yml up -d --build
```

`docker-compose.prod.yml` 会启动：
- `db`：PostgreSQL 16。
- `valve`：Flask/Gunicorn 应用。

### 3.4 使用服务器已有 PostgreSQL
如果服务器已经单独安装 PostgreSQL，可使用外部数据库部署文件，不再启动项目内置 `db` 容器：

```bash
cp .env.remote.example .env
```

编辑 `.env`，至少修改：

```env
DATABASE_URL=postgresql+psycopg2://valve:<数据库密码>@101.43.113.18:5432/valve
SECRET_KEY=<生产随机密钥>
ADMIN_PASSWORD=<管理员强密码>
DEMO_PASSWORD=<演示用户强密码>
SHOW_DEMO_CREDENTIALS=false
```

启动应用：

```bash
docker compose -f docker-compose.remote-db.yml up -d --build
```

如果应用容器和 PostgreSQL 在同一台 Linux 服务器，也可以使用：

```env
DATABASE_URL=postgresql+psycopg2://valve:<数据库密码>@host.docker.internal:5432/valve
```

部署前需要确认远程 PostgreSQL 已创建数据库和用户，并在 `listen_addresses`、`pg_hba.conf`、系统防火墙和云安全组中允许应用来源访问。

本机在 2026-04-22 对 `101.43.113.18:5432` 的检查结果：TCP 连接可建立，但 `psql` 协议连接被远端关闭，说明远程数据库配置仍需继续确认。

### 3.5 单容器运行说明
当前生产推荐 compose 方式，因为应用需要 PostgreSQL。若单独运行应用容器，需要自行提供可访问的 PostgreSQL，并在 `.env` 中配置 `DATABASE_URL`：

```bash
docker run -d --name valve-doc-platform \
  -p 8000:8000 \
  -v $(pwd)/data:/app/data \
  --env-file .env \
  --restart unless-stopped \
  valve-doc-platform
```

默认映射关系：
- 服务器本机 `127.0.0.1:8000` -> 容器 `8000`
- 对外访问建议由 Nginx 反向代理到 `127.0.0.1:8000`，不要直接暴露 compose 绑定地址。

默认健康检查地址：

```text
http://127.0.0.1:8000/healthz
```

### 3.6 访问系统
浏览器打开：`http://<服务器IP>:8000`

如果使用 `docker-compose.prod.yml`，则直接访问：

```text
先通过 Nginx 代理到域名，再对外访问域名地址
```

### 3.7 配置 Nginx 域名反向代理

项目已提供示例文件：

```text
deploy/nginx/yinyu990201.com.conf.example
```

在服务器上可按以下方式启用：

```bash
cp deploy/nginx/yinyu990201.com.conf.example /etc/nginx/sites-available/yinyu990201.com
ln -s /etc/nginx/sites-available/yinyu990201.com /etc/nginx/sites-enabled/yinyu990201.com
nginx -t
systemctl reload nginx
```

### 3.8 申请 HTTPS 证书

以 Ubuntu 为例：

```bash
apt update
apt install -y certbot python3-certbot-nginx
certbot --nginx -d yinyu990201.com -d www.yinyu990201.com
```

证书申请完成后，访问地址为：

```text
https://yinyu990201.com
```

## 4. 运维操作

### 4.1 查看日志
```bash
docker compose -f docker-compose.prod.yml logs -f valve
docker compose -f docker-compose.prod.yml logs -f db
```

### 4.2 停止与重启
```bash
docker compose -f docker-compose.prod.yml stop valve
docker compose -f docker-compose.prod.yml start valve
```

### 4.3 升级发布
```bash
git pull
docker compose -f docker-compose.prod.yml up -d --build
```

### 4.4 功能测试
本项目提供基于 `unittest` 和 Flask test client 的功能测试，覆盖登录、目录筛选、型号明细、解决方案、SUN 替代查询、询价预填、资料上传和普通用户权限。

本地测试命令：

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

发布前建议至少执行：

```bash
python -m unittest discover -s tests -p "test_*.py" -v
docker compose -f docker-compose.prod.yml config
docker compose -f docker-compose.remote-db.yml config
```

## 5. 生产建议
- 使用 Nginx 做反向代理并配置 HTTPS。
- 定时备份 `data/` 目录和 PostgreSQL volume/数据库。
- 建议接入监控告警（Prometheus + Grafana）。
- 若通过 HTTPS 对外提供访问，请把 `.env` 中的 `SESSION_COOKIE_SECURE=true`。
- 若登录页不希望展示默认账号，请把 `.env` 中的 `SHOW_DEMO_CREDENTIALS=false`。
- 插装阀目录默认数据由 `app/catalog.py` 种子化到 PostgreSQL，后续可改为后台维护。
- 型号 PDF 资料通过 `product_document.model_code` 和 `product_document.product_model_id` 关联到插装阀明细页。
- 数据库切换细节见：`docs/06-数据库切换说明.md`。
