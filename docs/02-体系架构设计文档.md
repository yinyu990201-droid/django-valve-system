# 企业级插装阀资料管理平台 - 体系架构设计文档

## 1. 总体架构
采用单体 Web 架构：

- 展示层：Flask + Jinja2 + Bootstrap（中文页面）。
- 业务层：Flask 路由 + RBAC 权限控制。
- 数据层：SQLite（可平滑迁移至 MySQL/PostgreSQL）。
- 文件层：本地持久化目录 `/app/data/uploads`。

## 2. 模块设计

### 2.1 认证模块
- 基于 Flask-Login 会话管理。
- 登录成功后写入 session。
- 路由装饰器控制登录与管理员权限。

### 2.2 资料管理模块
- `Document` 元数据入库。
- PDF 文件写入上传目录。
- 预览接口返回 `application/pdf`，前端 iframe 预览。
- 下载接口启用附件下载。

### 2.3 客户管理模块
- `Customer` 实体维护客户信息。
- 支持新增/修改/删除与列表展示。

### 2.4 权限控制模块
- 角色字段：`admin`、`user`。
- 管理员专属接口统一加 `admin_required`。

## 3. 数据模型

### 3.1 User
- `id`
- `username`（唯一）
- `password_hash`
- `role`
- `created_at`

### 3.2 Document
- `id`
- `title`
- `original_filename`
- `stored_filename`
- `description`
- `uploaded_by`
- `created_at`

### 3.3 Customer
- `id`
- `name`
- `contact_person`
- `phone`
- `email`
- `notes`
- `created_at`

## 4. 安全设计
- 密码使用 `werkzeug.security` 哈希。
- 上传仅允许 `.pdf` 后缀。
- 非管理员禁止访问管理接口（403）。
- 非登录用户重定向到登录页。

## 5. 扩展设计建议
1. 增加用户后台管理与密码策略。
2. 引入对象存储（S3/OSS）替代本地文件。
3. 增加 Elasticsearch 全文检索。
4. 新增客户分级、跟进记录、商机流程。
5. 接入审计日志和操作追踪。
