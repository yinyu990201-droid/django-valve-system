# 企业级插装阀资料管理平台 - 体系架构设计文档

## 1. 总体架构
采用单体 Web 架构：

- 展示层：Flask + Jinja2 + Bootstrap（中文页面）。
- 业务层：Flask 路由 + RBAC 权限控制。
- 数据层：PostgreSQL（测试环境可使用 SQLite 内存库）。
- 文件层：本地持久化目录 `/app/data/uploads`。
- 产品目录层：由 PostgreSQL 产品目录表驱动，`app/catalog.py` 提供查询、筛选和默认目录种子化服务。

## 2. 模块设计

### 2.1 认证模块
- 基于 Flask-Login 会话管理。
- 登录成功后写入 session。
- 路由装饰器控制登录与管理员权限。

### 2.2 资料管理模块
- `ProductDocument` 元数据入库，对应 SQLAlchemy 模型 `Document`。
- `Document.model_code` 关联插装阀型号，PDF 资料归属于具体型号明细页。
- PDF 文件写入上传目录。
- 预览接口返回 `application/pdf`，前端 iframe 预览。
- 下载接口启用附件下载。
- 旧 `/documents` 和 `/documents/upload` 页面入口保留路由兼容，但会引导回目录或型号明细页。

### 2.3 插装阀目录模块
- `app/catalog.py` 提供目录种子、数据库查询、筛选服务、分面选项和标签展示工具。
- `/catalog` 提供目录导航页，使用 GET 参数实现可分享的筛选状态。
- `/catalog` 对筛选后的结果进行服务端分页，分页链接保留当前 GET 查询参数。
- `/catalog/<model_code>` 提供型号明细页。
- `/quick-select` 提供问题式解决方案页面。
- `/sun-replacement` 提供 SUN 参考型号替代查询。
- `/contact` 提供询价信息整理页，并可由型号明细页带入候选型号。
- 默认目录数据在应用启动时写入 PostgreSQL；后续可接入 PIM/ERP 或后台维护界面。

### 2.4 客户管理模块
- `Customer` 实体维护客户信息。
- 支持新增/修改/删除与列表展示。

### 2.5 权限控制模块
- 角色字段：`admin`、`user`。
- 管理员专属接口统一加 `admin_required`。
- 目录、明细、解决方案、替代查询和询价页要求登录后访问，但不区分管理员与普通用户。

## 4. 安全设计
- 密码使用 `werkzeug.security` 哈希。
- 上传仅允许 `.pdf` 后缀。
- 非管理员禁止访问管理接口（403）。
- 非登录用户重定向到登录页。
- 目录查询使用 GET 参数，不执行写操作；询价页当前仅做信息整理，不写入数据库。

## 5. 扩展设计建议
1. 增加用户后台管理与密码策略。
2. 引入对象存储（S3/OSS）替代本地文件。
3. 增加 Elasticsearch 全文检索。
4. 新增客户分级、跟进记录、商机流程。
5. 接入审计日志和操作追踪。
6. 将默认目录种子进一步迁移到后台维护界面或产品主数据系统。
7. 为 SUN 替代关系增加正式审核状态、版本号、适配限制和附件资料关联。
