# 企业级插装阀资料管理平台 - 重构更新日志

## 2026-04-21 - 前端展示与产品目录重构

### 背景
本次重构目标是把原“资料与客户管理平台”升级为更贴近插装阀产品选型场景的目录型应用。设计参考来自用户提供的线框草图，以及 Sun Hydraulics 插装阀型号目录页的信息组织方式：顶部导航、目录列表、分面筛选、型号明细和型号替代查询。

参考页面：

```text
https://www.sunhydraulics.com/zh/models/cartridges
```

### 信息架构调整
- 将登录后的默认入口从 `/dashboard` 调整为 `/catalog`。
- 顶部导航调整为：插装阀目录、SUN型号替代、解决方案、联系询价、工作台。
- 原 `dashboard` 保留为工作台，不删除原有入口。
- 客户档案、登录、权限、健康检查和 Docker 部署链路全部保留；PDF 资料入口迁移到型号明细页。

### 新增后端模块
- 新增 `app/catalog.py`。
- 提供目录列表、型号查询、筛选、分面选项和标签展示工具。
- 2026-04-22 后，目录接口保持兼容，但底层改为 PostgreSQL 表查询和默认目录种子化。

### 新增路由
- `/catalog`：插装阀目录导航页。
- `/catalog/<model_code>`：型号明细页。
- `/quick-select`：解决方案页。
- `/sun-replacement`：SUN 型号替代页。
- `/contact`：联系询价页。

### 页面与交互
- 目录页采用左侧筛选栏 + 右侧结果表格结构。
- 目录页支持关键词、功能分类、控制问题、通口数、流量范围、压力等级、插孔型号和结构特征筛选。
- 筛选列表改为原生 `details/summary` 展开收起结构，默认展开前两个高频分组和已有选中项分组。
- 筛选栏顶部增加固定操作区，将“应用筛选”和“重置”移动到更容易触达的位置。
- 产品结果区增加服务端分页，默认每页 6 条，分页链接保留当前搜索、筛选和排序条件。
- 结果表格展示液压符号示意、型号、说明、SUN 参考型号、流量、压力、插孔和明细入口。
- 型号明细页展示液压符号、关键规格、替代说明、典型应用、相关型号和询价入口。
- 解决方案页采用问题式表单，按控制问题、通口数、流量范围和压力等级生成方案候选型号。
- SUN 型号替代页支持通过 SUN 参考型号、平台型号或插孔关键词查询。
- 联系询价页可从型号明细页带入型号、SUN 参考型号、流量、压力和插孔信息。
- PDF 上传、预览、下载和删除整合到型号明细页，管理员在当前型号下上传资料，普通用户在当前型号下预览和下载。
- 取消独立资料库页面界面，旧 `/documents` 和 `/documents/upload` 路由保留为跳转兼容。

### 视觉重构
- 将原偏展示型的渐变视觉改为工业产品目录风格。
- 使用白底、黑色线框、紧凑筛选栏、规格卡片和结果表格。
- 统一导航、按钮、表格、筛选项、提示和错误页样式。
- 为目录与明细页增加 SVG 液压符号示意，用于替代纯文字列表。

### 测试
- 新增 `tests/test_app.py`。
- 覆盖范围：
  - 健康检查与登录跳转。
  - 目录筛选页。
  - 目录分页与筛选参数保留。
  - 型号明细页。
  - 解决方案页。
  - SUN 型号替代页。
  - 联系询价预填。
  - 管理员 PDF 上传。
  - 普通用户禁止访问管理页面。
- 测试命令：

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

### 兼容性说明
- 未删除客户档案、PDF 预览/下载/删除能力；PDF 资料从独立资料库迁移为型号明细页附件。
- 2026-04-22 起，生产数据库切换为 PostgreSQL，测试环境仍可使用 SQLite 内存库。
- `app/catalog.py` 的函数接口保持不变，前端页面无需修改。

## 2026-04-22 - PostgreSQL 与后端数据库重构

### 后端调整
- 将 `User`、`Document`、`Customer` 扩展为 PostgreSQL 生产模型，并新增产品目录相关模型。
- 新增 `ProductModel`、`ProductCategory`、`ProductFunction`、`ProductTag`、`ProductFeature`、`ProductApplication`、`ProductCrossReference`。
- 新增 `CustomerContact` 和 `Inquiry`，为后续客户联系人、询价和解决方案流程扩展预留。
- `app/catalog.py` 保留原有查询函数名，但底层读取数据库，不再直接把静态常量作为页面数据源。

### 部署调整
- `requirements.txt` 新增 `psycopg2-binary`。
- `.env.example` 默认切换为 PostgreSQL 连接串。
- `docker-compose.prod.yml` 新增 `db` 服务，使用 `postgres:16-alpine` 和 `pgdata` volume。

### 文档调整
- 新增 `docs/05-数据结构设计文档.md`。
- 新增 `docs/06-数据库切换说明.md`。
- 更新 README、体系架构文档和部署文档中的数据库说明。

## 2026-04-22 - 远程 PostgreSQL 部署准备

### 连通性测试
- 从本机到 `101.43.113.18:5432` 的 TCP 连接可以建立。
- 使用 `psql` 连接 `postgres` 和 `valve` 数据库时，远端关闭 PostgreSQL 协议连接，当前不能确认账号、数据库和权限可用。
- 后续部署前需要在远程服务器确认 PostgreSQL 的 `listen_addresses`、`pg_hba.conf`、系统防火墙和云安全组均允许应用来源访问。

### 配置调整
- 新增 `.env.remote.example`，提供连接服务器已有 PostgreSQL 的环境变量模板。
- 新增 `docker-compose.remote-db.yml`，用于只启动应用容器并连接外部 PostgreSQL，不启动项目内置 `db` 容器。
- 保留 `docker-compose.prod.yml` 的原有本地数据库编排方式，避免影响当前可部署路径。
