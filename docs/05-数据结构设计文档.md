# 企业级插装阀资料管理平台 - 数据结构设计文档

## 1. 设计目标

本次后端重构将原先由 Python 静态常量驱动的插装阀目录，调整为 PostgreSQL 数据表驱动。设计目标如下：

- 覆盖当前全部功能：登录用户、插装阀目录、筛选、型号明细、SUN 型号替代、解决方案、PDF 型号资料、客户档案。
- 保持前端页面不变，通过后端模型属性兼容原模板使用的 `item.code`、`item.tags`、`item.features` 等字段。
- 为后续扩展预留空间：多来源型号替代、产品标签、产品应用场景、客户联系人、询价单、销售分配、资料版本。
- PostgreSQL 作为生产数据库，PDF 文件本体继续存储在 `/app/data/uploads`，数据库保存文件元数据。

## 3. 表结构设计

### 3.1 `app_user` - 系统用户表

| 字段 | 类型 | 约束 | 中文说明 |
|---|---|---|---|
| `id` | integer | 主键 | 用户 ID。 |
| `username` | varchar(80) | 唯一、非空、索引 | 登录用户名。 |
| `password_hash` | varchar(255) | 非空 | 使用 Werkzeug 哈希后的密码。 |
| `role` | varchar(20) | 非空、索引，默认 `user` | 用户角色，当前支持 `admin`、`user`。 |
| `full_name` | varchar(120) | 可空 | 用户真实姓名，预留用于内部人员管理。 |
| `email` | varchar(120) | 可空 | 用户邮箱，预留用于通知和账号管理。 |
| `active` | boolean | 非空，默认 `true` | 用户是否启用。 |
| `created_at` | timestamp | 非空 | 创建时间。 |
| `updated_at` | timestamp | 非空 | 更新时间。 |

## 4. 扩展设计

- 产品目录可继续拆分品牌、系列、插孔标准、密封材料、线圈、电气接口等专业表。
- `product_cross_reference` 支持不止 SUN 的外部型号替代。
- `product_document` 支持版本、可见性和文档类型，后续可扩展审批、归档和废止状态。
- `customer_contact` 和 `inquiry` 为后续 CRM 化、销售跟进、报价流程打基础。
- 当前应用仍使用 `db.create_all()` 建表，后续生产迭代建议接入 Alembic/Flask-Migrate 做正式迁移版本管理。
