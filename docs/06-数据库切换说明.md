# 企业级插装阀资料管理平台 - 数据库切换说明

## 1. 切换目标

本次重构将生产数据库从 SQLite 切换为 PostgreSQL。SQLite 仍可用于单元测试和临时本地验证，但生产部署推荐使用 PostgreSQL。

## 2. 依赖变化

新增 Python 依赖：

```text
psycopg2-binary==2.9.9
```

安装命令：

```bash
pip install -r requirements.txt
```

## 3. 环境变量

`.env.example` 已切换为 PostgreSQL 示例：

```env
DATABASE_URL=postgresql+psycopg2://valve:valve-password@db:5432/valve
POSTGRES_DB=valve
POSTGRES_USER=valve
POSTGRES_PASSWORD=valve-password
UPLOAD_DIR=/app/data/uploads
```

生产环境至少需要修改：

- `SECRET_KEY`
- `ADMIN_PASSWORD`
- `POSTGRES_PASSWORD`
- `DATABASE_URL`
- `SHOW_DEMO_CREDENTIALS=false`

## 4. Docker Compose 部署

`docker-compose.prod.yml` 已包含两个服务：

- `db`：PostgreSQL 16 Alpine。
- `valve`：Flask/Gunicorn 应用。

启动命令：

```bash
cp .env.example .env
docker compose -f docker-compose.prod.yml up -d --build
```

查看服务：

```bash
docker compose -f docker-compose.prod.yml ps
```

查看日志：

```bash
docker compose -f docker-compose.prod.yml logs -f valve
docker compose -f docker-compose.prod.yml logs -f db
```

PostgreSQL 数据持久化到 Docker volume：

```text
pgdata:/var/lib/postgresql/data
```

PDF 文件仍挂载到：

```text
./data:/app/data
```

## 5. 表结构初始化

应用启动时会执行：

1. `db.create_all()` 创建所有 SQLAlchemy 表。
2. `ensure_default_admin()` 初始化管理员和演示用户。
3. `seed_catalog_data()` 将默认插装阀目录写入 PostgreSQL。

默认目录种子只会插入尚不存在的型号，不会覆盖数据库中已有型号，便于后续接入后台维护。

因此首次部署无需手工建表。

## 6. 从 SQLite 迁移数据

当前项目历史数据较少，推荐生产切换时优先以 PostgreSQL 初始化新库，再按需要迁移旧资料。

如果需要迁移旧 SQLite 数据：

1. 备份旧目录：

```bash
cp -r data data-backup
```

2. 保留 PDF 文件：

```text
data/uploads/
```

3. 启动 PostgreSQL 后，重新上传或编写一次性脚本迁移 `document`、`customer`、`user` 数据到新表：

- 旧 `document` -> 新 `product_document`
- 旧 `user` -> 新 `app_user`
- 旧 `customer` -> 新 `customer`

4. 插装阀型号目录不需要从 SQLite 迁移，应用会通过 `seed_catalog_data()` 自动写入。

后续如果历史数据量变大，建议引入 Alembic/Flask-Migrate 和一次性迁移脚本。

兼容说明：应用启动期保留了旧 SQLite `customer` 表的轻量补列逻辑，方便本地开发继续打开历史数据库；生产 PostgreSQL 仍建议使用全新表结构初始化。

## 7. 本地开发

本地可直接使用 Docker PostgreSQL：

```bash
docker compose -f docker-compose.prod.yml up -d db
```

然后在 `.env` 中设置：

```env
DATABASE_URL=postgresql+psycopg2://valve:valve-password@localhost:5432/valve
```

再启动应用：

```bash
python run.py
```

## 8. 使用远程 PostgreSQL

如果目标服务器已经安装 PostgreSQL，可以不启动 `docker-compose.prod.yml` 中的 `db` 服务，改用远程数据库部署文件：

```bash
cp .env.remote.example .env
```

编辑 `.env`：

```env
DATABASE_URL=postgresql+psycopg2://valve:<数据库密码>@101.43.113.18:5432/valve
SECRET_KEY=<生产随机密钥>
ADMIN_PASSWORD=<管理员强密码>
DEMO_PASSWORD=<演示用户强密码>
SHOW_DEMO_CREDENTIALS=false
```

启动应用：

```bash
docker compose -f docker-compose.remote-db.yml up -d --build
```

如果 PostgreSQL 和应用容器部署在同一台 Linux 服务器，并且希望容器访问宿主机数据库，可把连接主机改为：

```env
DATABASE_URL=postgresql+psycopg2://valve:<数据库密码>@host.docker.internal:5432/valve
```

`docker-compose.remote-db.yml` 已配置 `host.docker.internal:host-gateway`。

远程数据库需要提前满足：

- 已创建 `valve` 数据库。
- 已创建可登录的 `valve` 用户，并拥有 `valve` 数据库权限。
- PostgreSQL `listen_addresses` 允许应用来源访问。
- `pg_hba.conf` 放行应用来源 IP 或 Docker 网段。
- 云安全组和服务器防火墙放行 `5432`。

本机在 2026-04-22 对 `101.43.113.18:5432` 的测试结果：

- TCP 连接可以建立。
- `psql` 协议连接被远端关闭，尚不能作为应用数据库使用。

## 9. 测试

单元测试仍使用内存 SQLite，保证不依赖本机 PostgreSQL 服务：

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

生产部署配置检查：

```bash
docker compose -f docker-compose.prod.yml config
docker compose -f docker-compose.remote-db.yml config
```

- `/catalog` 可显示插装阀目录。

- 管理员可在型号明细页上传 PDF。
- 普通用户可预览和下载 PDF，但不可上传。
- `docker compose -f docker-compose.prod.yml config` 无错误。
- `docker compose -f docker-compose.remote-db.yml config` 无错误。
- PostgreSQL volume `pgdata` 正常创建。
